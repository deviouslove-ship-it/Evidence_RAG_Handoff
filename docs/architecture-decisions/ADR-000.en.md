# ADR-000 — Handover decision for Evidence RAG and the USER desktop

Date: 2026-10-21 · Dossier version: 1.1 · Current SRS: v1.3.

**Status:** records the owner's direction and the documentation approach requested in the current chat. The technical defaults below are implementation choices that may be changed by an appropriate ADR; they do not replace business approval, permissions, security, Gold [Not implemented — see ADR-010], or acceptance on the target machine. No code has been implemented in this update.

## Context and requirement sources

Cross-checked directly against the chats “Thiết kế AI Agent tra cứu” (“Design an AI lookup agent”), “Mô tả AI Widget” (“Describe the AI Widget”), “Tiếp tục triển khai dang dở” (“Continue the unfinished implementation”), and “Khôi phục project RAG” (“Restore the RAG project”). The intent is established: separate administration from use; USER has a Windows app with login inside the app, a round Orb at the right corner of the desktop, and a chat/workspace that share RAG; model/key configuration may be entered later. History still records the bugs of a square background/faint shadow, a transparent login, drag overlapping the title, resize/collapse not working, and text that is too small; turn them into acceptance cases, and do not treat a previous fix/test as current evidence.

Version v1.2.1 is kept unchanged for traceability; the implementation set uses SRS v1.3 and dossier 1.1. Old code is not required to understand the requirements; do not copy test accounts, secrets, or machine paths into the specification.

## Installation rules the owner has finalized

`E:\Programs` is the mandatory root of the project's installed tools and runtime, not a default path embedded in the app. Deployment configuration is the only place that supplies the root value; executable/model/artifact/cache resolve from the manifest. LLM API/Local remains a matter of configuration and does not fix provider/model/endpoint. This documentation edit does not authorize actually installing or moving tools; the installation gates still require evidence in Sprint 0/4.

## Technical defaults and items that still need a decision-maker

- The proposed idle TTL for a temporary session is 30 minutes, and it is configurable; do not store anything long-term before retention is approved. Temporary session memory (RAM) connects directly to the interface through two-phase SSE streaming, and allows viewing the list, deleting a single item, deleting all of RAM, stopping (`Dừng`, Stop) or retrying (`Thử lại`, Retry) a turn, and saving/loading lookup preferences (`/memory/preferences`).
- Tauri 2 desktop shell, desired panel 380/420px, viewer minimum 480px + a 16px gap; clamp to the work area/platform API. Always-on-top OFF, turned on only according to the user's preference.
- Choose model/runtime/library through a POC that matches the capability; the Model Registry loads dynamic configuration from the DB with the generation parameters (`temperature`, `max_tokens`, `json_mode`), supports loopback/localhost for Local AI (Ollama/vLLM), filters the blacklist of sensitive secret_ref values, unwraps reasoning tags (`<think>`), limits the AI timeout to 70% to avoid 504, and degrades gracefully on its own.
- PostgreSQL FTS optimization: use `CROSS JOIN LATERAL` to compute `to_tsvector` once for each candidate record, eliminating CPU congestion and query latency when the data store is large.
- Profile B may demonstrate the offline core within the published limits; it does not replace the real-AI gate S3. A missing model/key only means the capability has not been checked; AI content must not be simulated in order to claim completion.
- The owner and the person who owns the business domain still decide business principles, scope/egress, retention and the backup retention period, domain, Gold [Not implemented — see ADR-010]/trap, thresholds after the baseline, and the real provider/model configuration. These points are not self-approved by an ADR.
